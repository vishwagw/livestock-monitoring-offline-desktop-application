# Handover package

This document lists everything delivered in the Livestock Counter project (Phases 1–4), how to rebuild
it from source, and what the receiving team should know.

## 1. Deliverables

| Deliverable | Location | Notes |
| --- | --- | --- |
| Spatial engine (Python package + CLI) | `src/livestock_engine/`, `pyproject.toml` | ray casting, UTM, DBSCAN de-duplication, dense-group mode, frame alignment, ingestion, validation |
| Desktop application | `desktop/` | Electron + React + Leaflet, offline, sandboxed |
| Standalone installers | built by `.github/workflows/release.yml` | Windows `.exe`, macOS `.dmg` (arm64/x64), Linux AppImage/`.deb`; no Python/Node/network needed |
| Integration guide + JSON Schemas | `docs/INTEGRATION_GUIDE.md`, `schemas/` | input formats, frame matching, outputs, CLI, Python API |
| Developer guide | `docs/DEVELOPER_GUIDE.md` | architecture, setup, tests, extension points |
| Build & release guide | `docs/BUILD_AND_RELEASE.md` | per-OS build environments, signing, release procedure |
| Performance & validation report | `docs/PERFORMANCE.md` | accuracy by scenario, dense groups, 55k–221k detections, UI at scale |
| Pilot guide | `docs/USER_GUIDE.md` | operating the app in the field |
| Third-party license inventory | `docs/THIRD_PARTY_LICENSES.md` | generated from installed metadata (`make licenses`) |
| Sample data | `examples/sample-flight/` | simulated DJI SRT, telemetry CSV, box CSV, ground truth |
| Build configuration | `requirements.lock`, `requirements-build.txt`, `requirements-dev.txt`, `desktop/package-lock.json`, `.python-version`, `desktop/.nvmrc`, `Makefile`, `packaging/`, `desktop/electron-builder.config.cjs` | pinned, reproducible |
| CI | `.github/workflows/ci.yml`, `release.yml` | tests, accuracy gate, packaged end-to-end checks, installers |
| Source-code package | `python packaging/make_source_package.py --ref <tag>` | reproducible zip + per-file SHA-256 manifest |

## 2. Rebuilding from scratch

```bash
git clone <repository> && cd livestock-monitoring-offline-desktop-application
python -m venv .venv && . .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt -r requirements-build.txt && pip install --no-deps -e .
pytest && livestock-engine benchmark --runs 5 --profile standard --profile sheep_pen
python packaging/build_engine.py
cd desktop && npm ci && npm test && npm run package && npm run test:release
```

See `docs/BUILD_AND_RELEASE.md` for per-OS details and signing.

## 4. Intellectual property and licensing

- All first-party source in this repository (the engine, desktop app, packaging scripts, tests and
  documentation) was written for this project.
- **The project's own license has not been chosen.** `desktop/package.json` says `UNLICENSED`
  (proprietary, all rights reserved), and there is no `LICENSE` file. The owner should add one before
  distribution.
- Third-party components are listed with their licenses in `docs/THIRD_PARTY_LICENSES.md`. They are
  permissive (MIT, BSD, Apache-2.0), except for:
  - `certifi`, which is MPL-2.0 (weak copyleft, file-level) and used unmodified;
  - GPL components covered by linking exceptions:
    - the GCC runtime (runtime library exception);
    - the PyInstaller bootloader (bootloader exception).
- Chromium's notices ship in every installer as `LICENSES.chromium.html`.
- The sample data in `examples/` is synthetic (generated by `livestock-engine simulate`) and contains
  no real farm or location data.

## 5. Open items and recommendations

| Item | Why it matters | Suggested action |
| --- | --- | --- |
| **Validate on real flights** | All accuracy figures are from simulation; real detectors, terrain and animal movement add error | Run `livestock-engine validate` on 3–5 real flights with gate counts or surveyed positions; tune the detector threshold and `eps` if needed |
| Code signing | Unsigned installers trigger SmartScreen / Gatekeeper prompts | Add certificates as CI secrets (docs/BUILD_AND_RELEASE.md §4) |
| Application icon | Installers use Electron's default icon | Add `desktop/build/icon.png` (1024×1024) |
| Project license | Needed before distribution | Choose and add a `LICENSE` file |
| Terrain | The ground is modelled as flat at take-off height | For hilly sites, add per-frame AGL from a DEM (ingestion hook in `ingest/assemble.py`) |
| macOS Intel runner label | GitHub retires runner images | Update `macos-15-intel` in `release.yml` if the job fails to start |
| Map tiles | The app reads a local XYZ tile folder; `npm run seed-tiles` needs a provider licensed for offline caching | Agree on a tile provider/licence, or run an internal tile server |

## 6. Support notes

- **Logs for a failed run:** the desktop app keeps the outputs of the last 5 runs (report, CSV, GeoJSON,
  audit) under the app's user-data folder (`runs/`).
- **Engine self-test from the install folder:** `resources/engine/livestock-engine self-check`.
- **Reproducing a field report:** export the **Report** and **Audit** from the app. Every detection's
  raw and aligned position and its assigned animal are recorded, so a count can be traced without
  re-flying.
